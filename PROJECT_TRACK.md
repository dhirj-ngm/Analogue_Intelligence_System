# Project working rules

The deliverable is a **complete local prototype** for analysts, researchers and
students to find and compare source-backed FMCG input-cost situations. Its scope
is the current twenty cases, local search, evidence inspection and comparison.
M013 is the final search pass. Do not start collection expansion, production
infrastructure or human review without a new user instruction.

Use **Discussion** for ideas and **Builder** for end-to-end implementation and
self-checks. The user does not need to grade cases or rankings or approve routine
work. Ask only for essential missing access, a paid service, destructive external
actions or a material change to the user's objective. Human validation is deferred;
R01 must not be contacted or sent the withdrawn packet again.

Read this file, STATUS.md and README.md on entry. Keep them short and factual:
README covers setup and limits, STATUS records actual completion/checks. Use Git
history for superseded plans. Do not create role prompts, module specs, handoffs
or review documents unless necessary to reproduce a result.

Preserve all case records and frozen M001 files. Keep publication/reporting dates,
source URLs/locations, attribution, metric definitions, scope and unknowns. Source
documents stay external. Company explanations and reported figures do not prove
that an action caused an outcome; continuing reports are not distinct situations.

Freeze evaluation inputs/expectations before changing search. Compare methods on
identical eligible cases, with public-information cutoffs, earlier reporting
periods and self/continuation exclusions. Rank from pressure passages only; keep
responses and outcomes out. Partial cases do not establish a combined situation.
AI judgements are development checks, never independent human validation.

Keep code in src/, tests in tests/, tools in scripts/, and reproducible inputs/results
in evaluation/. Run meaningful automated and desktop/mobile checks. Fix concrete
blockers, state known limits, commit and push when authorized. Prototype completion
does not require broad market coverage or production readiness.
